# 录音 VAD 与云端音频节流方案

本文记录原有的 PCM 节流方案。Prism 的语音输入现已改为原生 Ogg/Opus，按顺序上传容器头和全部录音分片。原 PCM 静音门控已移除。

## 1. 目标与边界

在眼镜端持续录音，只将需要识别的音频写入云端 ASR，降低用户开口前、长停顿和说完后的音频上行。优先保证识别内容完整，其次优化带宽。

用户仍通过单击停止本次语音输入，识别结果仍进入草稿，由用户确认发送。一次本地语音输入可以包含多个云端识别段；VAD 的段结束不等于用户停止输入，也不触发消息发送。

不引入基于音量阈值的替代检测器，不增加云端 VAD，不改变 Prism 消息协议。VAD 不识别内容、身份或目标说话人；其他人的讲话、电视人声仍可能上传。不能承诺零误判或固定节省比例。

## 2. 当前链路与节流位置

当前 `lib/voice-input.js` 在 `start()` 中创建一个 `SpeechRecognitionSession`，将 `RecorderManager.onFrameRecorded` 的全部 `frameBuffer` 排队写入 `session.audio.getWriter()`，停止录音后关闭 writer。

音频为 16kHz、单声道、16bit PCM，裸音频速率为 **32,000 B/s，约 256 kbit/s**。60 秒录音约 1.92 MB，尚不包含网络封装。

建议链路：

```text
原生录音 + 原生 VAD
        ↓ 音频分片及 true / false / undefined
本地上传门控 + 有界预录缓存
        ↓ 需要识别的 PCM，保持原始顺序
识别段调度器 → SpeechRecognitionSession → 云端 ASR
        ↓ 每段识别快照
整次输入的文字聚合 → 原有草稿 / 停止 / 确认发送
```

必须在 `writer.write()` 前完成门控。仅增加 `vad.enabled` 不会自动节流；用等长零 PCM 替代静音也不会节省这条 PCM 链路的音频字节。

## 3. 参数与音频完整性

| 项目 | 初始建议 | 用途与限制 |
| --- | --- | --- |
| 录音格式 | 保持 16kHz / mono / s16 PCM | 可按采样边界处理，无需拼接 WAV 头或处理编码器依赖 |
| 分片交付周期 | 目标约 100ms | 降低状态变化的观察延迟；实际周期取决于宿主 |
| 原生 VAD | enabled: true | 由宿主检测人声 |
| silenceDurationMs | 500ms | 由检测器保留短暂停顿；不是录音时长或 ASR 断句设置 |
| preRoll | 300ms | 在每次开口时补发此前尚未上传的音频，降低句首被截风险 |
| 边界保护 | 保留从 true 转为 false 的第一个完整分片 | 粗粒度状态不能说明分片内每个采样是否有人声 |
| 待写入音频总预算 | 4 秒 / 128,000 B | 覆盖待建会话、待写入及正在写入的数据；超限显式报错 |
| 会话启动、停止、最终结果超时 | 初始沿用现有 15 秒上限 | 音频缓存预算更早耗尽时，先按缓存超限处理 |

500ms 的尾部等待已由原生 VAD 执行，应用不再额外叠加一个 500ms 人声结束定时器。第一个 false 分片仅作为边界保护，不能保证补救全部误判。

预录按 PCM 字节计算：300ms 对应 9,600 B。缓存只保留尚未上传的音频，超出窗口时按 2B 采样边界裁掉最旧部分。持有音频副本，避免宿主复用 frameBuffer 后破坏排队数据。每个采样最多写入一个识别段，预录回放不得和上一段尾部重复。

项目当前使用 `frameSize: 250`，但本地参考文档没有声明该字段单位。实现前必须核对 wx API 的实际分片选项，**不能直接把它改成 100 并假定代表 100ms**。Web 文档里的 `MediaRecorder.start(100)` 也不能直接套用到 wx。

## 4. 门控规则

对每个有效音频分片先判断 `voiceActive` 的三态。空音频不产生上传，但须按实际宿主协议确认是否仍携带有意义的状态，不能因未知字段类型而关闭录音。

| 当前状态 | voiceActive | 行为 | 后续状态 |
| --- | --- | --- | --- |
| 等待开口 | false | 只更新 300ms 本地预录，不建云端会话 | 等待开口 |
| 等待开口 | true | 按顺序提交预录和当前完整分片，启动识别段 | 人声段进行中 |
| 人声段进行中 | true | 上传完整分片，包括原生 VAD 保留的短暂停顿 | 人声段进行中 |
| 人声段进行中 | false | 上传当前边界分片，然后结束该识别段 | 等待下次开口 |
| 等待下次开口 | false | 仅维护未上传的预录 | 等待下次开口 |
| 任意录音状态 | undefined / 非布尔异常值 | 补发未上传的预录和当前音频；本次输入余下时间切换为透传 | 降级透传 |
| 降级透传 | 任意 | 全部上传，直到用户停止 | 降级透传 |

降级在本次输入内保持，下一次输入重新尝试 VAD。这样不会在检测结果时有时无时反复开关上传，也不会把“没有检测结果”误当成静音。降级只保证从可回放窗口起透传，已经因明确 false 丢弃的旧音频无法恢复。

若自始至终只有 false，单击停止时丢弃预录，不创建 ASR 会话，走原有“没有听清”的结束流程。若自始至终没有检测结果，则从第一份音频起透传，行为接近现有全量上传。

## 5. 云端识别段与整次输入分离

建议采用 **一次本地录音、按人声段延迟创建云端会话**。理由是现有代码没有显式的音频间隙协议；长期停写同一个 writer 是否触发云端空闲超时、是否影响最终结果，尚无证据。分段结束时关闭 writer，让 ASR 正常完成，下一次开口创建新段。

- 无需上传音频时不创建云端会话，避免用户开口前的空闲连接。
- true 期间始终上传；第一次 false 保护分片排队完毕后关闭该段 writer，继续本地录音。
- 不能把“云端段 onend”直接转发为现有 `api.onend`，否则页面会退出语音输入。
- 每段保存一个识别结果快照，显示内容为“已完成段文字 + 当前段快照”。中间结果更新时替换本段快照，不重复累加 transcript。
- 段序号决定文字顺序；`runId + segmentId` 隔离迟到的 result、error、end。停止后仍接收当前合法段的最终修订，取消后忽略全部迟到结果。
- 每段内部结果是否为完整快照、如何使用 resultIndex，必须以新版 ASR 契约为准；当前页面简单遍历 results 的逻辑不能视为跨段聚合协议。
- 段间文字连接按语言与标点处理，不自动插入句号；英文词间保留必要空格，避免两个段直接粘成一个词。

初版只允许一个云端识别段处于写入或等待最终结果的阶段。上一段正在结束时，新开口音频进入有界队列，上一段结束后立即开启下一段并回放。若实测最终结果尾延迟导致队列经常积压，则串行方案不满足上线条件；须先确认宿主允许“旧段等待最终结果 + 新段接收音频”的受控重叠，再调整调度，不能无上限并发。

原生 VAD 500ms 会决定上传段边界，但不应擅自写入 `SpeechRecognitionSession.segmentation`。ASR 自身断句由其独立配置决定。若 ASR 在人声段尚未结束时主动 onend，应在已确认的协议下滚动开启下一段，不能直接结束本地录音；如果无法确认音频消费位置和结果归属，则显式提示失败，禁止盲目重播已提交音频。

与全量长连接相比，分段可能增加建连次数、尾延迟并降低跨段语言上下文。因此上线需同时测量识别质量、实际网络流量和时延。若宿主确认长连接支持稀疏音频、空闲保活及明确段结束协议，可将调度器替换为该协议，门控规则保持不变。

## 6. 停止、取消与错误

### 用户停止

1. 标记整次输入为 stopping，显式调用 `recorder.stop()`，继续接收停止过程中的最后分片。
2. 以宿主保证的末帧/停止事件顺序为边界封存输入；不能过早关闭 writer。
3. 已开启人声段或已降级时，按顺序写完有效音频并关闭 writer；等待所有已接纳段的最终结果。
4. 没有开启人声段时丢弃纯静音预录。已经封存并排队的下一段仍需识别完成。
5. 整次输入只触发一次 `api.onend`；页面恢复菜单，保留原有草稿确认流程。

如果宿主不保证 onStop 晚于末帧，必须使用其明确的 drain/末帧机制；不以拍脑袋延迟若干毫秒代替契约。

### 取消与资源释放

取消后使 run 失效，停止麦克风、abort 活动 writer，清空预录、待写音频和计时器，不等待识别结果。启动过程中取消，也必须在 recorder.start 最终返回后释放录音资源。

正常结束、ASR 提前结束、写入失败、启动失败、超时都走统一且幂等的清理路径。当前 `finish()` 主要清理计时器及错误时 abort writer，没有完整停止录音的处理；实现时需补齐，避免云端失败后麦克风继续工作。

RecorderManager 可能为共享实例，旧 run 的异步 stop 不得停止新 run 的录音。新输入应等待上一轮录音释放，或使用宿主提供的会话隔离能力。

### 背压与部分结果

writer.write 串行 await，按字节计入总预算，不用无限 Promise 链积压音频。超过 4 秒预算即停止录音并提示网络/识别服务繁忙；不静默丢弃人声音频，不无提示重试。

分段引入部分成功：前几段已完成、后续段失败时，保留“输入前草稿 + 本次已确认段”，剔除未确认的中间结果并提示重试。`lib/prism-page-voice.js` 目前在 onerror 时回滚至输入前草稿，需要同步调整，避免成功文字丢失。部分结果仍由用户确认发送。

## 7. 实现拆分

| 位置 | 责任 |
| --- | --- |
| 新增 `lib/voice-vad-gate.js` | 纯门控状态机、预录、采样边界、待上传片段及统计；不依赖 wx 或页面 |
| `lib/voice-input.js` | 启用宿主 VAD、创建识别段、背压、生命周期、结果聚合；保持 start/stop/abort 入口 |
| `lib/prism-page-voice.js` | 整次输入的开始/结束、部分成功保留；原有草稿和确认发送流程 |
| `lib/prism-trace.js` 及调用方 | 每次输入结束输出一份汇总统计 |
| `lib/i18n/*.js` | 若增加繁忙、部分成功提示，四语言同步 |
| `tests/voice-input.test.mjs` 及门控测试 | 三态、音频顺序、生命周期、背压和文字聚合 |

麦克风采集必须保留在允许的用户交互调用链中。能力查询可提前预热；不得因为等待 VAD 能力或云端会话创建，使录音启动脱离宿主要求的交互上下文。原生录音持续运行，VAD false 时只关上传门，不能 pause 麦克风，否则无法检测下一次开口。

## 8. 指标与节省估算

每轮记录 capturedBytes、writtenBytes、discardedBytes、abandonedBytes、unknownFrames、segmentCount、fallbackReason、queuePeakBytes、首个识别结果耗时、停止到最终结果耗时。writtenBytes 指 writer.write 成功接收，**不等于网络线上真实字节**；错误/取消时用 abandonedBytes 记录未交付数据，不能算作 VAD 节省。

正常完整结束时：`PCM 节省率 = discardedBytes / capturedBytes`。在全部缓存释放后，capturedBytes 应等于 writtenBytes + discardedBytes + abandonedBytes。另通过宿主网络统计测量音频封装、建连和其他协议开销。

示例：60 秒录音中，12 秒实际讲话、分成 3 段，假设每段额外保留 300ms 预录、500ms 检测尾部及 100ms 边界分片，则预计上传 14.7 秒，即约 470KB，裸 PCM 节省约 **75.5%**。这只是理想化估算；分片抖动、误判、段间重叠以及降级会改变结果。持续讲话时收益可能很小。

统计不包含音频内容、转写文字或凭据，不逐帧刷日志。

## 9. 验证与上线条件

### 先验证宿主契约

本地技能的 wx 文档只列出 frameBuffer，未列出 voiceActive、vad 选项或新版 SpeechRecognitionSession。用户提供的新文档确立了 VAD 三态语义，但提供的示例只有 Web 录音写法。因此实施前需从对应宿主版本的 wx 文档、类型定义或最小真机实验确认：

1. wx 的 VAD 开启参数、分片周期参数及单位；对未知选项是忽略还是报错；错误能否明确归因为“不支持 VAD”。
2. 16kHz PCM 下 voiceActive 是否可用，缓冲区归属、空分片行为、停止时末帧顺序，以及 VAD 是否确实在本地执行。
3. ASR 的创建时机、close 后 final/onend 行为、事件结果结构、主动端点规则、会话创建延迟及并发限制。

如果未知选项被忽略、回调没有检测结果，则按三态规则透传。如果 start 明确报告 VAD 不支持，后续以宿主允许的方式回退；如果错误不可区分，按真实录音错误处理，不能把权限错误也当成 VAD 兼容问题而重复申请麦克风。

### 自动化验收

- 全 false：上传零字节、云端零会话、录音继续至手动停止。
- 首帧 true：立即提交完整首帧；长静音后 true：只回放最近 300ms，内容顺序正确。
- 连续 true 与检测器保留的短暂停顿：全部透传；第一次 false 保留边界，后续 false 只留预录。
- 多次开口：逐采样验证无重复、无乱序；每段结果更新不重复追加，跨段文字连接正确。
- 第一帧或中途 undefined：补发待定预录、进入持续透传；此后 false 不再静音裁剪。
- 不规则分片长度、超过预录窗口的单个分片、复用 frameBuffer：按采样计算且缓存有界。
- 停止期间最后一帧、重复 stop、纯静音 stop、停止时有待识别段：末尾正确且只结束一次。
- 慢 writer、ASR 启动慢、前段 final 慢：总缓存不超预算，故障显式可见。
- 取消/重启、启动未完成时取消、旧段迟到回调、识别错误/超时：无串会话、无麦克风泄漏。
- 前段成功后段失败：保留已确认文字；原有草稿发送与自由回答流程回归通过。

### 真机对照

用相同音频对比 VAD 开关：安静、风噪、车辆、键盘、背景人声；轻声、短命令、句首弱辅音；中英文及长停顿；启动后立即说话、说话中立即停止；网络慢和长时间不说话。比较字符/词错误率、首尾截断、首字时延、结束时延、实际上行及段建连数。

上线门槛：自动化用例通过；确认没有可复现的新增首尾截断；识别质量和时延对照可接受；含明显静音的样本实际网络上行下降。具体质量与时延阈值根据基线数据确定，不能仅凭 PCM 丢弃比例判定成功。

保留内部总开关：关闭时回到现有全量 PCM 路径。先在测试设备验证，再开启默认行为；不在未知契约下直接假定所有固件均支持节流。

## 实施记录

已按 0.19.0 官方 media-capture 文档确认 wx 支持 vad，frameSize 单位为毫秒；当前采用 100ms 分片、500ms 静音等待、300ms 预录、首次 false 边界保护和未知状态持续透传。已增加 128KB 写入积压上限与结束时麦克风清理。已增加录音字节数、成功写入字节数、积压峰值、VAD 三态计数及停止阶段耗时诊断。尚未实现按人声段重建 ASR、部分段结果保留及完整丢弃字节统计；这些不应视为当前行为。
